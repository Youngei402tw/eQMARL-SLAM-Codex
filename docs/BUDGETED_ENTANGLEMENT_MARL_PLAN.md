# Budgeted entanglement routing for sequential multi-agent reinforcement learning

## Research question

Can a learned controller allocate a finite, consumable supply of Bell pairs across a changing multi-agent interaction graph so that decentralized agents obtain more long-horizon reward per entangled pair than static, random, or myopic allocation?

This program excludes active SLAM and excludes CHSH. It studies a new sequential resource problem: several pairwise private-information coordination requests arrive at each time step, only a matching of agent pairs can receive entanglement because one interface qubit cannot be Bell-paired with several partners simultaneously, each use consumes one pair, and the episode has a hard entanglement budget.

The proposed method is **BER-MARL** (Budgeted Entanglement Routing for MARL). Local agents learn or optimize decentralized measurement policies for a family of three-context binary-action coordination requests. A shared resource controller observes only public request metadata, remaining horizon, and remaining Bell-pair budget. It selects a feasible matching before private contexts are revealed. The resource controller never sees private observations or actions.

## Novelty screen and claim discipline

A bounded public-code and paper-metadata screen conducted on 2026-11-01 found:

- public entanglement-assisted MARL code centered on CHSH and static cell-free MIMO coordination (`SapthagiriM/eMARL`);
- a 2026 paper titled *The Sample Complexity of Quantum Entanglement Allocation* (arXiv:2609.10141), concerning learning which qubits should share entanglement from request history;
- no retrieved implementation or paper metadata combining a consumable Bell-pair budget, dynamic graph matching/monogamy constraints, decentralized MARL returns, and a learned long-horizon allocator.

This is evidence for a plausible gap, not proof of global novelty. The release must not claim “first” without a broader human literature review. The defensible contribution is a precisely specified sequential benchmark, an allocation algorithm, exact classical and quantum request-level certification, and held-out evidence about long-horizon resource efficiency.

## Sequential benchmark

There are four agents and a ten-step episode. At each step, a public request graph contains pairwise coordination requests. A request joins two agents, carries a public urgency multiplier, and has a public request type. Each endpoint privately observes a symbol in `{0,1,2}` and returns one binary action for that request. Its reward is its urgency-weighted payoff for satisfying a type-specific binary parity constraint. Private symbols are never revealed to the allocator or other agents.

Request types are generated by a committed hash-keyed process. Each type contains a `3 x 3` binary constraint table and positive integer context weights. The type's exact classical shared-randomness value is the maximum over all 64 deterministic local strategy pairs. Its quantum value is evaluated with local measurements on one Bell pair and bounded independently by the two-player XOR-game semidefinite program. Types with zero quantum-classical gap remain in the task family; the allocator must learn not to spend on them.

At a step, the allocator may choose any matching of active request edges. A selected edge consumes one Bell pair and uses the frozen entangled local policy. Unselected edges use the exact best classical decentralized policy. One agent cannot belong to two selected edges in the same step. Unused pairs carry forward. The public request process is Markovian and includes common low-value requests and rare high-urgency requests, making “spend immediately” suboptimal under a finite budget.

## Information and resource contract

- Local actors receive their own private three-valued context, request type, endpoint role, and the public entanglement allocation bit for that request.
- The allocator receives public graph, type, urgency, time, and remaining budget. It never receives private contexts.
- No post-context classical messages are allowed in the primary comparison.
- Pre-shared classical randomness is allowed. Because expected reward is linear in the local correlation, its optimum is certified by deterministic-strategy enumeration.
- Bell pairs are consumed on use. Circuit executions, simulated shots, pair uses, and classical public metadata are counted separately.
- A full-context classical controller and a per-request message controller are privileged references, not admissible zero-message controls.

## Methods

1. `classical_exact`: exact best zero-message local strategy for every request; no Bell pairs.
2. `quantum_random`: uniformly selects a feasible matching while budget remains.
3. `quantum_static`: uses a fixed allocation priority learned from development frequencies.
4. `quantum_greedy`: selects the largest current certified gains without valuing future requests.
5. `ber_marl`: shared-action DQN over feasible matching features, remaining budget, and horizon.
6. `dp_online_oracle`: model-aware, non-clairvoyant dynamic-programming allocator; reference upper bound for the registered public Markov process.
7. `future_clairvoyant`: sequence-aware knapsack/matching upper bound; descriptive only.
8. `message_oracle`: endpoint context exchange followed by optimal joint actions; privileged resource reference.

Every budgeted method receives the same request sequence, local policies, Bell-pair budget, feasible matchings, and pair accounting. The DQN input uses request values and public metadata rather than type IDs so held-out request types test generalization.

## Prospective outcomes

The primary seed-level outcome is total **entanglement surplus**: episode return minus the exact classical zero-message return on the same sequence. Secondary outcomes are total return, surplus per consumed Bell pair, unused pairs, fraction of the non-clairvoyant DP surplus, deadline/urgency strata, and performance with finite-shot local policies.

The confirmatory study targets 16 independent allocator-training seeds and at least 1,000 paired held-out sequences per seed. Request types and sequence streams are disjoint from development. A positive BER-MARL result requires all of:

1. the two-sided paired-seed 95% bootstrap interval for `BER-MARL surplus - greedy surplus` has lower bound above zero;
2. the mean improvement over greedy is at least 5% of the DP oracle's mean surplus;
3. the one-sided 95% lower bound for BER-MARL's fraction of DP surplus exceeds 0.90;
4. the one-sided 95% lower bound for BER-MARL surplus over the classical zero-message baseline exceeds zero;
5. all Bell-pair matching and budget constraints hold exactly.

Failure of any condition prohibits a superior-allocation claim. Request-level quantum gaps and allocator-level gains are reported separately. The experiment does not claim computational speedup or hardware advantage.

## Data and development separation

Stage 21 commits development, validation, and final request-type manifests before learning. Development may inspect request-level values and train policies. Validation selects among at most four DQN configurations using fixed development/validation seeds. The final type manifest and final sequence RNG keys are hash-locked and cannot guide architecture or hyperparameters. Stage 23 uses final checkpoints only and retains every failed seed.

## Compute budget

Each stage retains the existing 24 cumulative active wall-hour cap, one training job at a time, at most eight CPU threads, and no paid compute. Request-level certification is limited to two qubits per selected edge. Stage 21 benchmarks SDP and local-policy optimization before Stage 22 freezes the matrix. Stage 22 may use at most four DQN configurations, two development seeds each, followed by four pilot seeds. Stage 23 targets 16 seeds and no more than 10,000 allocator episodes per seed, reduced prospectively if the measured convergence and precision gates permit.

## Stages

### Stage 20 — prospectus and novelty screen

Publish this plan, related-work screen, task generator identity, inference rules, budgets, and claim boundaries before reportable implementation outcomes. Gate: the proposal is sequential, resource-constrained, excludes SLAM/CHSH, and has falsifiable classical, quantum, allocation, and publication criteria.

### Stage 21 — certified request family and sequential environment

Implement hash-keyed request generation, exact classical enumeration, Bell-policy optimization, independent XOR-game SDP bounds, graph matching, budget accounting, Markov sequences, privileged references, and archive schemas. Gate: classical values are exact; optimized quantum values never exceed SDP bounds and achieve registered numerical tolerance on fixtures; information isolation, monogamy, budget, replay, and seed-split tests pass.

### Stage 22 — bounded algorithm development and freeze

Optimize local request policies, train/tune BER-MARL with equal opportunities, compare allocation controls on development/validation only, benchmark compute, and freeze all final seeds, streams, update limits, metrics, inference, and failure rules. Gate: local quantum gaps are reproducible and the allocator is capable of testing the primary question without final-manifest access.

### Stage 23 — locked held-out confirmation

Train fresh allocator seeds and evaluate final checkpoints on paired held-out types and sequences. Preserve all outcomes and run the registered inference exactly. Positive, null, and negative results all complete the stage; only the five-part gate supports a superior budgeted-allocation claim.

### Stage 24 — independent audit and paper release

Validate every bundle and checkpoint, independently recompute request certificates and primary inference, reproduce representative sequences, publish paper tables and claim limits, and verify fresh remote retrieval. Gate: the final report distinguishes the new sequential resource result from request-level nonlocal-game theory and makes no unsupported priority claim.

## Publication boundary

A positive result would support a new algorithmic and benchmark contribution: learned allocation of consumable entanglement across a dynamic MARL interaction graph, with exact request-level controls and held-out long-horizon evidence. It would not prove a new Bell theorem, quantum computational speedup, hardware advantage, or superiority when private observations can be communicated freely.
